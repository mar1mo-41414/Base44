# Base44

人間が見間違えにくい 44 文字だけを使う、独自の Base44 エンコーダ / デコーダ。
GNU coreutils の `base64` / `base32` コマンドと同じ形式の CLI コマンド `base44` として、
C で書かれたネイティブバイナリで実装している。

> **注意: 本プロジェクトの Base44 は標準規格ではありません。**
> QR コード向けなどで使われる既存の Base44 とは文字セットも変換方式も異なる、
> 本プロジェクト独自の仕様です。他の Base44 実装との互換性はありません。

実用上の目的は特にありません。「Base44」という名称を見てエンコード方式だと思ったら
アプリケーションサービスの名称だった、という経緯から、実際に Base44 を作ってみた趣味プロジェクトです。
ただし変換の正確性・可逆性・仕様の一貫性はきちんと確保しています。

## 文字セット

以下の 44 文字を、この順序で固定して使います。順序はそのまま各文字の数値
(0〜43) への割り当てになります。

```
ABCDEFGHJKMNPQRTUYabcdefghjkmnpqrtuy23456789
```

| 種別 | 文字 | 数 |
| --- | --- | --- |
| 大文字 | `ABCDEFGHJKMNPQRTUY` | 18 |
| 小文字 | `abcdefghjkmnpqrtuy` | 18 |
| 数字 | `23456789` | 8 |
| 合計 | | 44 |

### 除外した文字と理由

以下の 18 文字は、形状や表示環境によって見間違い・読み間違い・OCR 誤認が
起きやすいため除外しています。

```
0 1 I i L l O o S s V v W w X x Z z
```

たとえば `0` と `O`、`1` と `l` と `I`、`5` と `S`、`2` と `Z` のような
混同が起きないよう、似た形の文字は片方だけを残すか両方とも外しています。

## 変換方式

単なる文字置換ではなく、44 進数変換による可逆エンコードです。

### エンコード

- 入力はバイト列として扱い、ビッグエンディアンで処理する
- 2 バイト (16 bit) のブロックを整数として読み、44 進数 **3 桁固定** に変換する
- 末尾に 1 バイト (8 bit) の端数がある場合は、44 進数 **2 桁固定** に変換する
- ブロックの並び順は入力順のまま。符号にヘッダー・区切り・メタデータは付けない

桁数を固定することで、先頭の 0 相当の桁が失われず、デコード時に文字数から
ブロック構造を判別できます。

数値的な裏付け:

- 44^1 = 44 < 256 なので 1 バイトを 1 桁では表せない
- 44^2 = 1936 >= 256 なので 1 バイトは 2 桁で安全に表せる
- 44^3 = 85184 >= 65536 なので 2 バイトは 3 桁で安全に表せる

### デコード

- 文字を数値 0〜43 に戻し、ブロックごとにバイト列を復元する
- 有効な符号長は `mod 3` が 0 か 2 のものだけ。`mod 3 == 1` は不正な桁数として拒否する
- 2 桁ブロックの値が 256 以上、3 桁ブロックの値が 65536 以上の場合は
  オーバーフローとして拒否する (エンコードでは生成され得ない値のため)
- 文字セット外の文字は、位置と文字を示してエラーにする。不正なデータを黙って補正しない

### 変換例

以下は独立な実装 (Python) でも生成・相互検証した検証済みの値です。

| 入力 | バイト列 (hex) | Base44 |
| --- | --- | --- |
| (空) | `` | `` |
| 1 バイト 0x00 | `00` | `AA` |
| 1 バイト 0xFF | `ff` | `Fy` |
| 2 バイト 0x00 0x00 | `0000` | `AAA` |
| 2 バイト 0xFF 0xFF | `ffff` | `t3b` |
| `A` | `41` | `Bd` |
| `Hi` | `4869` | `KhQ` |
| `Hello` | `48656c6c6f` | `KhKRR2Cf` |
| `Base44` | `426173653434` | `JuKTNYG5r` |
| `こんにちは` (UTF-8) | `e38193e38293e381abe381a1e381af` | `pDnbgbYNqpDnerDYGKpDnD9` |
| 😀 (UTF-8) | `f09f9880` | `qy9cHP` |

テキストを変換する場合は、文字列を UTF-8 のバイト列にしてから Base44 化します。
CLI はバイナリ透過なので、テキストでもバイナリでも同じ経路で処理できます。

## ビルドとインストール

必要なのは C11 対応の C コンパイラと libc だけです。依存ライブラリはありません。

```bash
git clone <このリポジトリ>
cd Base44
make          # ./base44 がビルドされる
make test     # 自動テスト (Python 3 が必要)

# コマンドとして置く場合 (デフォルトは ~/.local/bin/My/ へ)
make install

# インストール先を変える場合
make install PREFIX=/usr/local BINDIR=/usr/local/bin
make install DESTDIR=/tmp/stage
```

## 使い方

`base64` / `base32` と同じ感覚で使えます。

```bash
# ファイルをエンコード
base44 file.bin

# デコードしてファイルに戻す
base44 -d file.b44 > restored.bin

# パイプで使う
echo -n 'Hello' | base44            # -> KhKRR2Cf
echo -n 'KhKRR2Cf' | base44 -d      # -> Hello

# 折り返しを無効化 (GNU base64 と同じく末尾改行も付きません)
base44 -w 0 file.bin

# 10 桁で折り返し
base44 --wrap=10 file.bin

# デコード時に文字セット外のゴミを無視する
base44 -d -i dirty.b44 > restored.bin
```

### GNU base64 との対応

| やりたいこと | base64 | base44 |
| --- | --- | --- |
| エンコード | `base64 file` | `base44 file` |
| デコード | `base64 -d file` | `base44 -d file` |
| 折り返し指定 | `base64 -w 76 file` | `base44 -w 76 file` |
| ゴミを無視してデコード | `base64 -i file` | `base44 -i file` |
| ヘルプ | `base64 --help` | `base44 --help` |
| バージョン | `base64 --version` | `base44 --version` |

オプション一覧 (`base44 --help`):

```
Usage: base44 [OPTION]... [FILE]
  -d, --decode          decode data
  -i, --ignore-garbage  when decoding, ignore non-alphabet characters
  -w, --wrap=COLS       wrap encoded lines after COLS character (default 76).
                          Use 0 to disable line wrapping
      --help            display this help and exit
      --version         output version information and exit
```

FILE を省略するか `-` を指定すると標準入力から読みます。
FILE が 2 つ以上指定された場合はエラーになります。

## 開発

```
src/base44.h       変換コアの公開 API
src/base44.c       変換コア (バイト列ベース、入出力に依存しない)
src/main.c         CLI 本体 (オプション解析は getopt_long)
test/core_test.c   コア API の全数テストハーネス (C)
test/test_base44.py  Python 3 標準ライブラリのみの CLI テスト
Makefile           make / make test / make install / make clean
```

コアの公開 API (`src/base44.h`):

- `base44_alphabet` — 固定文字セット (44 文字)
- `base44_encode(const uint8_t *data, size_t len, size_t *out_len, base44_error *error)`
  — バイト列を Base44 文字列へ。戻り値は malloc された文字列
- `base44_decode(const char *text, size_t len, size_t *out_len, base44_error *error)`
  — 厳密デコード。戻り値は malloc されたバイト列
- `base44_error` — エラーの詳細 (状態コード、問題の位置、ブロック値など)
- `base44_error_format()` — エラー詳細を人間可読なメッセージに整形する

他の C プログラムから使う場合は、`src/base44.c` を一緒にコンパイルして
`src/base44.h` を include してください。

テストの実行:

```bash
make test
```

テストは二段構成です。

1. **コア全数テスト** (`test/core_test.c`): コア API を直接叩く C ハーネス。
   エンコードは 1 バイト全 256 値・2 バイト全 65,536 値、デコードは
   2 文字全 1,936 通り・3 文字全 85,184 通りを全数検証し (範囲外は
   オーバーフローで失敗することまで含む)、全 2 バイト値の符号を連結した
   196,608 文字の一括往復、不正桁数・不正文字の位置やエラー詳細、
   文字セット定数そのものも確認します。アサーションは 961,893 件です。
2. **CLI テスト** (`test/test_base44.py`): Python 3 標準ライブラリのみで
   ビルド済みバイナリを叩く 52 メソッド。検証済みベクトル、長さ 1..6 の
   段階列、全バイト値・1MiB の往復、符号の性質 (使用文字・長さの公式)、
   折り返しの幅マトリクスと `-w` の境界値、空白や `-i` の扱い、
   オプションの結合・省略形、ファイル系エラー、エラー時に stdout へ
   何も出ない保証、パイプ連結の往復に加えて、GNU base64 と
   exit コードの符号が一致するかの並行比較も行います。

## 性能測定

2026-11-20 に実測した、GNU coreutils 9.4 の `base64` との比較です。
測定環境は x86-64 Linux (Core i3-8100) です。

### 大きなバイナリファイル

対象は 102,655,717 バイト (約 98MiB) のバイナリファイルです。
エンコード・デコードとも各 5 回実行した中央値で、出力は /dev/null に
捨てて変換速度のみを測っています。

| 処理 | base64 | base44 |
| --- | --- | --- |
| エンコード | 0.138 s (約 744 MB/s) | 0.335 s (約 306 MB/s) |
| デコード | 0.477 s (約 215 MB/s) | 0.679 s (約 151 MB/s) |

MB/s は元データのサイズ基準です。

| 出力サイズ | バイト数 |
| --- | --- |
| base64 | 138,675,270 (元データの約 1.35 倍) |
| base44 | 156,009,676 (元データの約 1.52 倍) |

出力が大きいのは、2 バイトを 3 文字で表す Base44 の符号方式によるものです。
どちらの往復でも復元結果の sha256 が元データと一致することを確認しています。

### 小さいテキストファイルの連続処理

ランダムなテキスト 100 ファイル (各 102,400 バイト) を、1 ファイルずつ
エンコード → デコードする処理を 5 周した中央値です。

| base64 | base44 |
| --- | --- |
| 0.395 s | 0.431 s |

小さいファイルの連続処理ではプロセス起動と I/O が支配的で、差は約 9% でした。

### 所感

素朴な実装としては悪くない数値で、本ツールは趣味プロジェクトですし、
現状の性能で実用上問題はありません。速さが欲しくなったら、その時に
改善するかも知れません (特に差が大きいエンコード側が狙い目です)。

## 制約事項

- **入力は全読み込み方式です。** CLI は入力全体をメモリに読み込んでから処理します。
  巨大なファイルではメモリ使用量が入力サイズに比例します (デコード時は、
  検証が全て通ってから一括出力するためにも必要な方式です)。
  ただしバッファは動的に伸長するので、固定長の上限はありません。
- **空白の扱い:** コアの `base44_decode()` は厳密で、空白を含む文字セット外の
  文字はすべてエラーにします。一方 CLI のデコードは、折り返された符号を
  そのまま流し込めるよう、まず ASCII 空白 (改行・空白・タブ等) を
  フレーミングとして除去してから厳密デコードします。それ以外の不正文字は
  エラーになります。空白以外のゴミも除去したい場合は `-i` を使ってください。
- **ファイル名や MIME タイプは保持しません。** base64 と同様、符号自体に
  メタデータは含まれません。復元後のファイル名は利用者側で管理してください。
- 文字セットと変換方式は本プロジェクト独自仕様であり、他の Base44 実装や
  Base64 / Base32 との互換性はありません。
